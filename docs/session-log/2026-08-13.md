### Bônus — `-race ./...` rodado no WSL e mais 1 race REAL corrigido

Antes do push, rodei o job de race do CI localmente: **3 testes do
`internal/system/tray` quebraram por DATA RACE** — o que o CI teria revelado
na primeira execução. O race estava nos **mocks do teste** (não no controller):
`populatePresetMenu` (goroutine de background) escrevia `title`/`children` dos
`mockMenuItem` enquanto a goroutine do teste lia via `itemByTitle` — e o
`mockSystray.items` era appendado sem lock. Fix: mutex cobrindo todos os
campos mutáveis dos mocks + accessors (`getTitle`, `getTooltip`,
`childrenCount`, `child`, `iconCallCount`, `itemByTitle` com lock).
**Resultado: `go test -race ./...` 100% verde no Linux.**

## Decisões importantes

- **Race em `./...` (não lista fixa)** — manter a lista de 15 pacotes exigia
  lembrar de ampliá-la a cada pacote novo; `./...` nunca mais precisa disso e
  é o que o plano pede. Custo: a primeira execução pode revelar data races
  reais nunca vistos (o pacote do daemon nunca rodou sob `-race`) — esperado.
- **`gofmt -l .` no CI é seguro** — o index do repo guarda tudo em LF
  (`git ls-files --eol`: só 2 binários fora de LF); o CRLF que o `gofmt -l`
  acusa no Windows local é artefato do `core.autocrlf=true` do checkout, não
  existe no runner ubuntu.
- **Não mexi nos testes `requireRoot` do daemon** — eles Skip sem root e o
  runner do CI é não-root; deixar herméticos (dir injetável) fica como item
  para rodar a suíte como root (Etapa 0 do plano anota isso).

## Etapa 3 executada — enforcer real ponta a ponta (WSL2/Ubuntu, daemon root)

Ciclo completo do `enforcer_linux.go` contra o kernel real (iptables
v1.8.11 nf_tables):

- **`block example.com 30m`** ✅ — hosts com `# FOCUSGUARD:` (4 entradas,
  127.0.0.1 + ::1 + www), REJECT `--reject-with tcp-reset` + ICMP por IP nas
duas famílias (`icmp6-port-unreachable` no v6, nft aceita), **curl ao IP
bloqueado falha em 0ms com `Connection refused` (o RST do REJECT)**, e site
não-bloqueado (example.org → HTTP 200) segue funcionando (bloqueio cirúrgico).
- **Pânico + allowlist** ✅ — `block --internet --allow google.com,docs.google.com
  --duration 2m`: ACCEPT `FOCUSGUARD_ALLOW` por IP **antes** do catch-all
  REJECT `FOCUSGUARD_ALL` por família; curl ao IP permitido → HTTP 200;
  resto (inclusive DNS) cortado (esperado). **Na expiração (timer real), o
  UnblockAll varreu os marcadores nas duas famílias — 0 regras all/allow
  restantes, sem órfãs**, e os blocos de domínio continuaram intactos.
- **DoH/DoT** ✅ — com blocos ativos o scheduler aplica `--dport 853` DROP
  (tcp+udp, 2 famílias) + 443 por provider (20 regras v4). `dns start` no WSL
  falha no bind :53 (stub — quirk conhecido) exibindo o hint Linux do
  systemd-resolved (regressão do achado 1 confirmada). `dns stop` desliga o
  sinkhole; **as regras DoH ficam enquanto houver bloco ativo e somem quando o
  último expira** (cenário validado: estado vazio → `focusguard status` mostra
  "Proteção DoH/DoT: inativa", 0 regras de firewall).
- **Rollback de batch** ✅ — quebrei `ip6tables-restore` (script que sai 1) e
  bloqueei `wikipedia.org` (IPv6): `ip6tables-restore restore falhou` →
  **hosts sem entrada, 0 regras REJECT do domínio, sem bloco zumbi no
  estado** (rollback total, como o teste unitário). Binário restaurado.
- **Reboot/reconciliação** ✅ — `wsl --shutdown` com 3 blocos ativos: hosts
  regenerado pelo WSL (0 FOCUSGUARD), firewall limpo (kernel novo), estado
  persistido intacto. Subi o daemon → **reconciliou: 12 entradas hosts + 12
  regras REJECT + DoH reaplicados, e VARREU 2 regras órfãs plantadas
  (203.0.113.99 v4 + 2001:db8::99 v6)**. Bloqueio real voltou a valer
  (curl falha).

**Achado INFO (não bug):** `ss -K` não mata conexões no kernel do WSL2 — o
kernel Microsoft (`6.18.33.2-microsoft-standard-WSL2`) compila **sem
`CONFIG_INET_DIAG_DESTROY`** (`/proc/config.gz` confirma), então o `ss -K`
retorna "RTNETLINK answers: Invalid argument" e a conexão segue viva. O design
já é best-effort e o backstop funciona: com o bloco ativo, o próximo pacote
leva RST do REJECT — validado ao vivo (conexão estabelecida morreu com
`ConnectionResetError` no 1º pacote após o block). Em kernel Ubuntu real o
`CONFIG_INET_DIAG_DESTROY` é ligado e o `ss -K` derruba na hora — registrar
como INFO do WSL (teste de conexão ativa fica para a máquina real).

**Nota de metodologia:** `wsl --terminate <distro>` NÃO reinicia o kernel — o
WSL2 moderno compartilha uma VM entre distros, então o firewall (estado do
kernel) sobrevive ao terminate do distro; o reset completo exige
`wsl --shutdown` (a VM toda). Usado para o teste de reboot real.
